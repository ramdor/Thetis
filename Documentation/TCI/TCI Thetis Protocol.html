Scope

This document supplements the public Expert Electronics TCI Protocol Ver. 2.0 document dated 12 January 2024, published at https://github.com/ExpertSDR3/TCI. It does not replace the original specification. The official Expert Electronics document remains the base reference for the generic TCI grammar, transport model, and command families.

Purpose

This supplement records the current Thetis interpretation of the protocol, including Thetis mappings for selected standard TCI 2.0 commands, Thetis behaviour differences, and Thetis custom commands that are not part of the official Expert Electronics 2.0 document.

Audience

This document is intended for client developers, integrators, automation authors, and maintainers working against the Thetis TCI server.

1 Introduction

1.1 Document Scope

This document covers the parts of TCI 2.0 where Thetis has implementation detail that matters to clients. It focuses on Thetis differences from the base protocol and on Thetis messages that fall outside the official Expert Electronics 2.0 specification.

1.2 Relationship To The Official 2.0 Protocol

The official Expert Electronics document remains the baseline command grammar reference. This supplement records Thetis behaviour when those commands are used against the Thetis TCI server. In the CW terminal family, the published Protocol 2.0 document differs from observed command usage in ExpertSDR 3, so the Thetis notes for those commands have been validated against ExpertSDR 3 v1.1.7.

Reading Rule

If a command is defined in the official 2.0 document and not called out here, clients should assume the official Expert Electronics behaviour model first. If a command is called out in this supplement, the Thetis note in this document takes precedence for Thetis interoperability.

2 Thetis Implementation Overview

Thetis presents itself as a TCI 2.0 style server, but several command families map onto existing Thetis subsystems rather than separate internal protocol objects.

3.2 Locking, Noise Processing, And Extended Receiver State

Command Direction Thetis behaviour Example
VFO_LOCK Notification + control Mapped onto Thetis VFO A / VFO B lock model. When RX2 is enabled, VFO B is represented on receiver 1 channels. vfo_lock:1,0,true;
VFO_SYNC_EX Bidirectional Thetis extension for VFO sync state. Use no arguments to query, or a single boolean to enable or disable synchronisation. vfo_sync_ex:true;
VFO_SWAP_EX Unidirectional Thetis extension that swaps the active VFO assignments immediately. This is a bare command with no arguments. vfo_swap_ex;
RX_NR_ENABLE / RX_NR_ENABLE_EX Bidirectional rx_nr_enable exposes simple on/off NR state. rx_nr_enable_ex adds the active NR algorithm index. Get requests return both forms. rx_nr_enable_ex:0,true,2;
RX_NB_ENABLE / RX_NB_ENABLE_EX Bidirectional rx_nb_enable exposes simple on/off NB state. rx_nb_enable_ex adds the selected NB algorithm index. rx_nb_enable_ex:0,true,1;
RX_NF_ENABLE Bidirectional Maps to Thetis manual notch, MNF, not MNF+ notch creation. rx_nf_enable:0,true;
RX_STEP_ATT_ENABLED_EX Bidirectional Thetis extension for step attenuator enable state by receiver. rx_step_att_enabled_ex:0,true;
RX_STEP_ATT_EX Bidirectional Thetis extension for step attenuator value in dB by receiver. This field defines attenuation directly, so values are positive dB attenuation amounts. rx_step_att_ex:0,10;
RX_PREAMP_ATT_EX Bidirectional Thetis extension for preamp gain behaviour. This field is gain oriented; when the preamp path is being used as an attenuator, attenuation is expressed using negative values. Positive values are currently ignored by Thetis. rx_preamp_att_ex:0,-10;
RX_CTUN_EX Bidirectional Thetis extension for CTUN state by receiver. rx_ctun_ex:0,true;
FM_DEVIATION_EX Bidirectional Thetis extension for FM deviation selection by receiver query context. Current supported set values are 2500 and 5000 Hz. fm_deviation_ex:0,2500;
AGC_AUTO_EX Bidirectional Thetis extension for AGC auto mode enable state by receiver. agc_auto_ex:0,true;
TX_FILTER_BAND_EX Bidirectional Thetis extension for TX filter low/high edges. Query with no arguments, or set with low/high values in Hz. Thetis normalises values to non-negative low/high order and enforces a minimum 100 Hz span. tx_filter_band_ex:100,2900;

VFO_LOCK Routing

When RX2 is disabled, vfo_lock:0,0 refers to VFO A and vfo_lock:0,1 refers to VFO B. When RX2 is enabled, vfo_lock:0,0 stays on VFO A and VFO B is represented on receiver 1 using vfo_lock:1,0 and vfo_lock:1,1.

Step Attenuator And Preamp Convention

  • rx_step_att_ex defines attenuation in dB, so client values are positive attenuation amounts such as 10, 20, or 30.
  • rx_preamp_att_ex defines the amount of gain on the preamp path. When that path is being used as attenuation, the attenuation is represented by negative values such as -10 or -20.
  • Values above 0 are currently ignored for rx_preamp_att_ex.

3.3 Display Stream Control

Thetis implements a display stream control family that drives receiver spectrum subscriptions. Display output is sent as compact WebSocket binary payloads described in section 3.4.

Command Direction Thetis behaviour Example
DISPLAY_START Bidirectional Starts or reconfigures a display stream subscription for receiver 0 or 1. The current implementation requires the 11-field form <rx>,<pixels>,<fps>,<fft>,<window>,<detector>,<average_mode>,<average_time_ms>,<one_hz>,<min_dbm>,<max_dbm>. display_start:0,1024,15,8192,4,0,2,250.0,true,-140.0,-20.0;
DISPLAY_STOP Bidirectional Stops the display stream subscription for the selected receiver. When the last subscription is removed, the internal spectrum processor is disposed for that TCI client. display_stop:0;
DISPLAY_PIXELS Bidirectional Sets the display line width. Thetis accepts values in the range 64 through 32768. display_pixels:0,2048;
DISPLAY_ZOOM Bidirectional Sets zoom level from 0.0 to 1.0 and a zoom centre frequency in Hz. Thetis replies with the normalised zoom and also sends display_pan with the resulting pan value. display_zoom:0,0.650000,7074000;
DISPLAY_PAN Bidirectional Sets pan position from 0.0 to 1.0. While zoomed in, this clears the explicit zoom centre tracking state for the receiver. display_pan:0,0.500000;
DISPLAY_DELTA_MODE Control Enables or disables delta capable display publication for the selected active display subscription. When disabled, block delta mode is also disabled. display_delta_mode:0,true;
DISPLAY_BLOCK_DELTA_MODE Control Enables or disables block delta display publication. Enabling block delta also enables normal delta mode for that receiver. display_block_delta_mode:0,true;
DISPLAY_ACCURACY_MODE Control Sets display compression tolerance. Values 0 through 4 are quantised byte thresholds. Value 5 enables an automatic threshold based on roughly 0.5 dB resolution. display_accuracy_mode:0,5;
DISPLAY_ADAPTIVE_BLOCKS Control Enables adaptive block size selection for block delta payloads. Thetis chooses the smallest payload from block sizes 64, 32, 16, and 128. display_adaptive_blocks:0,true;
DISPLAY_KEYFRAME_INTERVAL Control Sets the maximum number of delta frames between raw frames. Values are clamped to 0 through 1000000. 0 disables the forced keyframe interval. display_keyframe_interval:0,30;
DISPLAY_QUANT_BITS Control Sets the number of bits used to quantise raw display samples. Thetis clamps to 6, 7, or 8 bits. display_quant_bits:0,7;
DISPLAY_FRAMERATE Bidirectional Sets the target display update rate in frames per second. Thetis accepts values in the range 1 through 120. display_framerate:0,25;
DISPLAY_FFTSIZE Bidirectional Sets the spectrum FFT size. Thetis works within 4096 through 262144 and normalises the request to the nearest power of two in that set. display_fftsize:0,16384;
DISPLAY_WINDOW Bidirectional Sets the spectrum window type index. Thetis accepts values in the range 0 through 6. display_window:0,4;
DISPLAY_DETECTOR Bidirectional Sets the detector type index for the panadapter path. Thetis accepts values in the range 0 through 4. display_detector:0,1;
DISPLAY_AVERAGING Bidirectional Sets the averaging mode index. Thetis accepts values in the range 0 through 3. display_averaging:0,2;
DISPLAY_AVERAGE_TIME Bidirectional Sets averaging time in milliseconds. Thetis works within 1.0 through 9999.0 ms. display_average_time:0,250.0;
DISPLAY_ONE_HZ Bidirectional Enables or disables one hertz normalisation. Thetis accepts true/false and also 1/0. display_one_hz:0,true;
DISPLAY_DBM_RANGE Bidirectional Sets the quantisation range used when Thetis converts display dBm values into outbound display values. Each endpoint is limited to -200.0 through 200.0 dBm. If max is not greater than min, Thetis applies a minimum 1 dB span. display_dbm_range:0,-140.0,-20.0;
DISPLAY_DUPLEX Notification Reports the Thetis display duplex state. In local MOX, a receiver display shows TX data when display duplex is disabled; otherwise it continues to show receiver data. display_duplex:false;

Display Setting Examples

  • Start a compact RX1 feed: display_start:0,1024,15,8192,4,0,0,120.0,false,-140.0,-20.0;
  • Enable delta and block delta compression: display_delta_mode:0,true; then display_block_delta_mode:0,true;
  • Use adaptive blocks and 7 bit raw quantisation: display_adaptive_blocks:0,true; then display_quant_bits:0,7;
  • Force a raw keyframe roughly every 30 display updates: display_keyframe_interval:0,30;
  • Zoom to a frequency and then pan within the zoomed view: display_zoom:0,0.650000,7074000; then display_pan:0,0.500000;

Display Stream Notes

  • Thetis exposes display subscriptions for receiver indexes 0 and 1 only.
  • The current display_start handler requires exactly 11 arguments. The older 6-field form is no longer accepted by this implementation.
  • Changing pixels, frame rate, FFT size, window, detector, averaging, average time, one hertz state, dBm range, zoom, pan, or display compression settings resets the saved prior frame, so the next update is sent as a raw compact display payload.
  • When the display frequency span or left edge changes, Thetis resets display compression state and sends a raw compact display payload.
  • All display compression controls apply to an existing active subscription. Start the display stream before setting compression controls.

3.4 Compact Display Binary Payload

Thetis display binary frames now use a compact display payload rather than the earlier 64-byte stream header used by audio and IQ streams. The payload starts with the ASCII magic bytes T and D, followed by a one byte version field.

Offset Field Description
0 Magic 0 84, ASCII T
1 Magic 1 68, ASCII D
2 Version 1
3 Payload kind 0 = raw, 1 = delta, 2 = block delta, 3 = use previous frame
4 Receiver Receiver index, normally 0 or 1

Raw Payload Kind 0

Offset Field Description
5 Quantisation bits 6, 7, or 8
6..9 Hz left Little endian unsigned 32 bit value for the left edge of the display span
10..13 Hz span Little endian unsigned 32 bit value for the display span width
14..17 Logical pixel count Little endian unsigned 32 bit value for the number of display points
18.. Sample payload Raw quantised display samples. At 8 bits, this is one byte per pixel. At 6 or 7 bits, values are packed most significant bit first.

Delta Payload Kind 1

Offset Field Description
5 Delta bits Bits used for each signed delta. Thetis uses 2 through 7 according to the largest per pixel change.
6.. Delta payload Each value is packed most significant bit first and is decoded as packed - ((1 << (bits - 1)) - 1), then added to the previous frame value.

Block Delta Payload Kind 2

Offset Field Description
5 Block size Block size used for this payload. Default is 64. With adaptive blocks enabled Thetis may use 64, 32, 16, or 128.
6.. Block mode table and data The first ceil(pixel_count / block_size) bytes are block modes. Mode 0 means raw block bytes follow, mode 1 means unchanged block, and modes 2 through 7 mean a packed delta block using that number of delta bits.

Use Previous Frame Payload Kind 3

Kind 3 carries only the common 5 byte compact header. It tells the client to reuse the previous decoded display frame for that receiver. Thetis emits this kind only when delta mode is enabled and the new quantised display frame is unchanged after the active accuracy threshold is applied.

Client Decode Rules

  • Expect the first frame after display_start to be raw because no previous frame exists.
  • Store the latest decoded frame for each receiver. Delta, block delta, and use previous frame payloads are relative to that stored frame.
  • Use the most recent raw payload metadata for pixel count, left edge, span, and quantisation depth until the next raw payload arrives.
  • If the client loses any compact display binary frame, it should ignore later delta or block delta payloads for that receiver until the next raw payload arrives.

3.5 Sensors, Audio Negotiation, And Opus Codec Settings

The Thetis TCI server supports optional sensor polling plus negotiated RX/TX audio streaming. Current code supports both PCM audio transport and Opus codec negotiation.

Command Direction Thetis behaviour Example
RX_SENSORS_ENABLE Control Enables or disables periodic RX sensor reports. Optional second argument sets the interval in milliseconds. rx_sensors_enable:true,200;
RX_SENSORS_ENABLE_EX Control Enables or disables compact per receiver/channel RX sensor reports. Fields are receiver index, channel index, enabled state, and optional interval in milliseconds. This causes Thetis to publish the short sr report for the selected pair. rx_sensors_enable_ex:0,0,true,200;
SR Reply Compact RX sensor report emitted by the extended RX sensor subscription. Fields are receiver index, channel index, signal dBm, average signal dBm, peak bin signal dBm, and noise floor dBm. sr:0,0,-71.5,-73.2,-69.8,-118.4;
TX_SENSORS_ENABLE Control Enables or disables periodic TX sensor reports. Optional second argument sets the interval in milliseconds. Reports use tx_sensors:<rx>,<mic_dbm>,<rms_watts>,<peak_watts>,<swr>;. tx_sensors_enable:true,200;
AUDIO_RECONFIGURE_BEGIN Control Begins a grouped audio reconfiguration. Audio compression reset and queued TX audio clearing are deferred until the matching end command unwinds the reconfiguration depth to zero. audio_reconfigure_begin;
AUDIO_RECONFIGURE_END Control Ends a grouped audio reconfiguration. When the nesting depth returns to zero, any deferred RX audio reset and TX audio queue clear are applied. audio_reconfigure_end;
AUDIO_SAMPLERATE Bidirectional Sets negotiated audio sample rate. In PCM mode Thetis accepts the standard TCI set 8000, 12000, 24000, and 48000. In Opus mode it also accepts 16000. audio_samplerate:48000;
AUDIO_CODEC Bidirectional Selects the negotiated audio codec family. Thetis accepts pcm and opus. audio_codec:opus;
AUDIO_STREAM_SAMPLE_TYPE Bidirectional Selects TX/RX audio sample encoding. Thetis accepts int16, int24, int32, float32, and also opus as a shorthand that switches the codec family to Opus. audio_stream_sample_type:float32;
AUDIO_STREAM_CHANNELS Bidirectional Selects audio stream channel count. Thetis accepts 1 or 2. audio_stream_channels:2;
AUDIO_STREAM_SAMPLES Bidirectional Selects the negotiated audio packet sample count. Thetis accepts values from 20 to 4096. In Opus mode, only sizes that map to a valid Opus frame duration at the current sample rate are applied. audio_stream_samples:2048;
TX_STREAM_AUDIO_BUFFERING Bidirectional Controls TX audio buffering in milliseconds. Thetis accepts values from 50 to 500. tx_stream_audio_buffering:50;
AUDIO_OPUS_APPLICATION Bidirectional Sets Opus application mode. Thetis accepts audio, voip, and lowdelay. audio_opus_application:audio;
AUDIO_OPUS_SIGNAL Bidirectional Sets Opus signal hint. Thetis accepts auto, voice, and music. audio_opus_signal:voice;
AUDIO_OPUS_BANDWIDTH Bidirectional Sets the Opus bandwidth hint. Thetis accepts auto, narrowband, mediumband, wideband, superwideband, and fullband. audio_opus_bandwidth:fullband;
AUDIO_OPUS_BITRATE Bidirectional Sets Opus target bitrate in bits per second. Thetis works within 6000 through 510000 bps. audio_opus_bitrate:64000;
AUDIO_OPUS_VBR Bidirectional Enables or disables Opus VBR mode. audio_opus_vbr:true;
AUDIO_OPUS_CVBR Bidirectional Enables or disables constrained VBR mode. audio_opus_cvbr:false;
AUDIO_OPUS_COMPLEXITY Bidirectional Sets Opus encoder complexity. Thetis accepts values in the range 0 through 10. audio_opus_complexity:10;
AUDIO_OPUS_FEC Bidirectional Enables or disables in band forward error correction. audio_opus_fec:true;
AUDIO_OPUS_DTX Bidirectional Enables or disables Opus DTX. audio_opus_dtx:false;
AUDIO_OPUS_PACKET_LOSS Bidirectional Sets expected packet loss percentage for encoder tuning. Thetis accepts values in the range 0 through 100. audio_opus_packet_loss:5;
AUDIO_OPUS_FRAME_MS Bidirectional Sets Opus frame duration in milliseconds. Thetis normalises to 2.5, 5, 10, 20, 40, or 60 ms, then updates audio_stream_samples to the matching sample count. audio_opus_frame_ms:20.0;

Grouped Audio Reconfiguration

Clients can wrap several audio negotiation commands between audio_reconfigure_begin; and audio_reconfigure_end;. This lets Thetis defer RX audio compression reset and queued TX audio clearing until all related settings have been applied.

audio_reconfigure_begin; can be nested. The deferred reset only occurs when matching audio_reconfigure_end; calls reduce the depth back to zero.

Sensor Polling Behaviour

  • Requested RX and TX sensor intervals are limited by Thetis to 30 through 1000 ms.
  • When sensors are enabled, Thetis fires the first timer immediately, then continues at the negotiated interval.
  • Normal RX reports are published as rx_sensors, rx_channel_sensors, and Thetis rx_channel_sensors_ex.
  • Extended RX sensor subscriptions use rx_sensors_enable_ex:<rx>,<channel>,<enabled>[,<interval_ms>]; and publish the compact sr report with signal, average signal, peak bin, and noise floor values.
  • TX reports are published as tx_sensors with mic level dBm, RMS power watts, peak power watts, and SWR, and are currently mirrored on both receiver indexes for compatibility.

Audio Negotiation Defaults

  • Thetis starts with audio_codec:pcm;, audio_stream_sample_type:float32;, audio_stream_channels:2;, and tx_stream_audio_buffering:50;.
  • The default PCM audio sample rate is 48000. The default sample count helper produces 256 at 8 kHz, 512 at 12 kHz, 1024 at 24 kHz, and 2048 at 48 kHz.
  • In Opus mode, 16000 is also accepted and maps to a default sample count of 512.
  • When Opus is selected, Thetis publishes sample type opus and keeps audio_stream_samples aligned with the active Opus frame duration.

Frame Size Examples

  • At 48000 Hz, audio_opus_frame_ms:2.5; maps to audio_stream_samples:120;.
  • At 48000 Hz, audio_opus_frame_ms:10.0; maps to audio_stream_samples:480;.
  • At 48000 Hz, audio_opus_frame_ms:20.0; maps to audio_stream_samples:960;.
  • At 16000 Hz, audio_opus_frame_ms:20.0; maps to audio_stream_samples:320;.

3.6 CW And KEYER Support Via CWX

Thetis implements the TCI CW family using CWX as the execution engine. This keeps remote CW behaviour aligned with the native Thetis CWX subsystem rather than creating a second CW transmit path.

Command Direction Thetis behaviour Example
CW_MACROS_SPEED Bidirectional Controls CWX macro speed. cw_macros_speed:30;
CW_MACROS_DELAY Bidirectional Controls CWX PTT delay. cw_macros_delay:100;
CW_KEYER_SPEED Bidirectional Controls Thetis keyer speed. cw_keyer_speed:24;
CW_MACROS_SPEED_UP Unidirectional Raises CWX macro speed. cw_macros_speed_up:5;
CW_MACROS_SPEED_DOWN Unidirectional Lowers CWX macro speed. cw_macros_speed_down:3;
CW_MACROS Bidirectional use Sends CW text through CWX. cw_macros:0,cq cq de mw0lge;
CW_TERMINAL Bidirectional use Enables or clears terminal mode in the Thetis CW controller. Thetis expects the receiver qualified form validated against ExpertSDR 3. cw_terminal:0,true;
CW_MSG Bidirectional use Structured prefix / callsign / suffix send using CWX. cw_msg:0,tu,mw0lge,599 001;
CW_MACROS_STOP Unidirectional Stops the active TCI CW owner and releases TX even if terminal mode remains enabled. cw_macros_stop;
CW_MACROS_EMPTY Notification Sent in terminal mode when the last queued character starts transmitting. Thetis emits the receiver qualified form validated against ExpertSDR 3. cw_macros_empty:0;
CALLSIGN_SEND Notification Sent when the callsign portion of cw_msg has been transmitted. callsign_send:mw0lge;
KEYER Unidirectional Uses the CWX key path for timed key down / key up operation. keyer:0,true,0;

Observed CW Protocol 2.0 Deviations

  • The published TCI 2.0 PDF shows cw_terminal:true; and cw_terminal:false;, but ExpertSDR 3 v1.1.7 uses receiver qualified forms such as cw_terminal:0,true; and cw_terminal:0,false;.
  • The published TCI 2.0 PDF shows cw_macros_empty;, but ExpertSDR 3 v1.1.7 emits cw_macros_empty:0;.
  • Thetis follows the receiver qualified forms above for compatibility with observed Expert Electronics Protocol 2.0 behaviour.
  • In terminal mode, Thetis remains in TX after the macro queue drains until an explicit cw_terminal:<rx>,false; or cw_macros_stop; is received.

KEYER Behaviour In Thetis

  • keyer is implemented through CWX, not through the macro text queue.
  • The selected TX side must already be in cwl or cwu.
  • keyer:0,... selects TX on VFO A. If RX2 is enabled and TX is currently on VFO B, Thetis forces TX back to VFO A first.
  • keyer:1,... only operates when RX2 is enabled and forces TX to VFO B before the CW mode check.

4 Standard Reconciliation And Thetis Extensions

This section separates official Expert Electronics TCI 2.0 commands from messages that are currently Thetis specific. The official protocol is still the base reference; this table records how the current Thetis server differs from, extends, or omits parts of that base.

4.1 Official 2.0 Commands That Are Not Thetis Custom Commands

The uploaded official TCI 2.0 text already defines several commands that were previously listed in this supplement as custom. They remain documented elsewhere only where Thetis behaviour differs.

Command Official 2.0 status Thetis note
SPOT_CLEAR Standard Official TCI 2.0 command for deleting all spots from the panorama. Thetis implements it through its spot manager.
SPOT_DELETE Standard Official TCI 2.0 command for deleting a single spot. Thetis accepts one argument and passes it to the spot manager delete path.
CLICKED_ON_SPOT Standard notification Official legacy spot click notification. Thetis emits clicked_on_spot:<callsign>,<frequency_hz>;.
RX_CLICKED_ON_SPOT Standard notification Official receiver/channel qualified spot click notification. Thetis emits receiver index, channel index, callsign, and frequency.
LINE_OUT_START / LINE_OUT_STOP Standard Official line out stream controls. Thetis maps the receiver argument onto its available line out / VAC controls when the setup form is available.

SPOT JSON Payload In Arg5

Thetis accepts a structured JSON payload in the fifth spot argument by appending [json] immediately before the JSON object. The parser treats the JSON block as part of the same spot command even when it contains commas, quotes, or nested braces.

Command Format

spot:<callsign>,<mode>,<frequency_hz>,<argb>,[json]{...};

spot:g4abc,cw,7025000,4294967295,[json]{"Spotter":"m0xyz","Comment":"Loud on dipole","Heading":45,"Country":"England","UtcTime":"2025-06-25T16:45:30Z","TextColor":"#ffd700","Flag":"gb","FlagSpotter":"gb","Distance":128,"IsSWL":false,"SWLSecondsToLive":0};

JSON property Type Current Thetis behaviour
Spotter string Stored and displayed as the spotter callsign or source label.
Comment string Used as the spot comment text and replaces the plain arg5 free text field when JSON is present.
Heading integer Beam heading in degrees. Values outside 0 to 360 are treated as not present.
Continent string Accepted by the JSON schema, but the current Thetis add spot path does not populate the stored spot continent from this field.
Country string Stored as the spot country. If omitted, Thetis may derive country and flag information from the callsign prefix.
UtcTime string UTC timestamp in the form yyyy-MM-ddTHH:mm:ssZ. If parsing fails or the field is omitted, Thetis uses the current UTC time.
TextColor string Optional text colour override parsed by Thetis spot colour handling.
Flag string Optional flag asset code for the spotted station, using the ANSI two letter country code.
FlagSpotter string Optional flag asset code for the spotter, using the ANSI two letter country code.
Distance integer Optional distance in kilometres. When present, Thetis stores the supplied value with the spot.
IsSWL boolean Optional to mark the spot as SWL only behaviour for Thetis spot lifetime management.
SWLSecondsToLive integer Optional SWL expiry in seconds. Negative values are treated as 0.

When JSON is used, Thetis deserialises arg5 into its internal JsonSpotData class and passes both the raw JSON text and parsed object into spot creation. If JSON deserialisation fails, the spot is ignored. The parser looks specifically for the marker [json]{ inside the spot command. Without [json], all content from arg5 onward is joined back together as free text.

5 Compatibility Notes

5.1 Reference Recommendation

Client authors should continue to use the official Expert Electronics TCI 2.0 document as the baseline reference. Where the published document conflicts with observed command usage, especially in the CW terminal family, Thetis interoperability notes in this supplement take precedence.

5.2 Display Client Guidance

  • Use the 11-field display_start form. The older 6-field form is not accepted by the current Thetis implementation.
  • Detect display binary frames by the leading bytes 84,68,1, which represent TD version 1.
  • Keep a decoded previous frame for each receiver because delta, block delta, and use previous frame payloads depend on it.
  • Ignore delta payloads until a raw payload has been received for that receiver.
  • After any loss of binary display data, wait for the next raw payload before resuming delta decode for that receiver.

5.3 Validated Protocol 2.0 Deviations And Omissions

  • cw_terminal: the published document shows a single boolean argument, but Thetis follows the receiver qualified form used by ExpertSDR 3 v1.1.7, for example cw_terminal:0,true;.
  • cw_macros_empty: the published document shows a bare notification, but Thetis emits the receiver qualified form used by ExpertSDR 3 v1.1.7, for example cw_macros_empty:0;.
  • Terminal TX hold: terminal mode remains in TX after queued CW completes and only drops on explicit terminal clear, stop, disconnect, or other hard abort conditions.

5.4 Routing And Receiver Topology

Several commands in Thetis map onto the VFO A / VFO B model rather than a strict one command per receiver abstraction. This is most visible in lock, vfo_lock, and keyer when RX2 is enabled.

5.5 CW Mode Preconditions

Thetis does not silently force a non CW mode into CW for TCI CW operations. TCI CW activity is expected to operate only when the selected TX side is already in cwl or cwu.

5.6 Client Guidance

  • Use the official Expert Electronics 2.0 document for generic command grammar and message sequencing, but prefer the validated ExpertSDR 3 v1.1.7 CW terminal forms when they differ from the PDF.
  • Use this supplement for Thetis routing, AGC mapping, CW/CWX behaviour, sensor negotiation, compact sr reports, stream negotiation, VFO sync/swap helpers, display compression, round trip rt echo checks, official command deviations, and Thetis extension messages.
  • Prefer tx_frequency_ex rather than the retired tx_frequency_thetis extension when you need Thetis band and TX routing context.
  • Treat CW ownership as exclusive in Thetis.
  • Do not assume that all TCI receivers in Thetis map directly to independent hardware or DSP chains.
